# 0008. Hand-written SQL migrations, no drizzle-kit

- **Status:** Accepted
- **Date:** 2026-11-24
- **Deciders:** Ahmed Oraby (owner), architecture review

## Context

The SQL that protects stock (the CHECK, the partial unique index, the conditional updates) must stay visible and reviewable. `drizzle-kit` brought 4 moderate advisories, and it is a dev-only generator we don't need.

## Options considered

| Option | For | Against |
|---|---|---|
| Migrations generated by drizzle-kit | less typing | hides the SQL; advisories; one more tool |
| **`migrations/*.sql` + journal, applied by drizzle-orm's migrator** | the SQL is reviewed as written; reproducible | the schema is written twice (SQL + Drizzle `schema.ts`) |

## Decision

Migrations are written by hand. Each module's Drizzle `schema.ts` mirrors its SQL, and a schema-parity test fails if they differ.

## Consequences

- No generator in the toolchain; the parity test catches drift.
- Optional extensions (pgvector) are handled in the SQL itself ([0018](0018-pgvector-hnsw-with-fallback.md)).
